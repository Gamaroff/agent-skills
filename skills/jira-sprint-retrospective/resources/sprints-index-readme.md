# Sprint Retrospectives

One document per sprint, written at or just after sprint close, recording what was committed, what
was discovered mid-sprint, what carried over, and what the delivery data says. Written to be read
during the next sprint's planning session.

## What this is not

- **Not the backlog.** A retrospective describes a sprint that has closed; it never becomes a
  competing queue.
- **Not the per-increment record.** Where a project writes a summary per delivered story or task,
  these sit a layer above: one per sprint, describing the sprint.
- **Not a tracker replacement.** The board is the live state. These are dated snapshots of it, and
  they say so.

## Conventions

**One file per sprint.** The name comes from `retrospective.filenamePattern` in `skills-config.yaml`,
default `sprint.{n}.retrospective.md`.

**Declare the scope in frontmatter.** A retrospective covering named people sets `scope:` to those
names; one covering the whole sprint sets `scope: all`. Scope is a property of the analysis, not of
the filesystem — retrospectives are never split into per-person directories. Where a sprint needs
several people covered, the file grows sections rather than the tree growing branches.

**Date every figure, and record how to re-derive it.** Each retrospective ends with a
`How this was measured` section carrying the commands behind its numbers and the date they were run.
Sprint figures decay as soon as the board moves.

**Add a row above** when a retrospective is added, and update the existing row rather than appending
when one is regenerated.

## On back-links

A retrospective links out to the issues it covers and is owed no links back. It is a periodic record,
not a companion of any one work item, and back-linking it from every issue it mentions would mean
editing a dozen documents per sprint for no reader's benefit.

## A note on link scope

A retrospective can only link to documents that exist on the branch it is written from. Work sitting
on an integration branch is real and worth recording, but its card may not be linkable yet —
reference it by issue key and say where it lives.

# Task 20 — Pre-`/qa-story` traceability mapper subagent

**Status**: Planned

> Detailed implementation guide: [task.20.plan.qa-story-traceability-mapper-subagent.md](task.20.plan.qa-story-traceability-mapper-subagent.md)

## 1. Overview

`/qa-story` builds an AC → spec-files → src-files traceability matrix internally. Today this happens in main context, requiring multiple greps and reads.

**Scope**: extract this mapping into a read-only Explore subagent dispatched by the orchestrator (or by `/qa-story` itself in lite-mode) before assessment begins. `/qa-story` accepts a caller-supplied matrix and skips internal mapping when provided.

## 2. Motivation

- Mapping greps + file reads bloat main context before assessment work begins.
- Caller-supplied matrix lets `develop-story` orchestrator parallelise mapping with other Step-5 prep.

## 3. Technical Background

**Current**: `skills/qa-story/SKILL.md` performs traceability mapping inline as part of its review.

**Target**: orchestrator dispatches Explore: "Read story <path>, extract ACs, grep for related spec files (`*.spec.*`, `*.test.*`) and src files, return matrix as markdown table." Pass result via env var or temp file. `/qa-story` lite-mode contract accepts `traceability_matrix_path` arg.

## 4. Scope

**In**: traceability mapping handoff.
**Out**: `/qa-story` assessment logic; gate file generation.

## 5. Breaking Changes

None — additive contract; absent matrix arg → existing behaviour.

## 6. Implementation Plan

### Phase 1 — Define matrix schema (Low)
- [ ] Markdown table: AC | Spec files | Src files | Coverage notes
- [ ] Document arg name `--traceability-matrix <path>`

### Phase 2 — Author Explore prompt (Low)
- [ ] Strict matrix output; ≤30 rows
- [ ] Patterns to grep configurable per project

### Phase 3 — Wire orchestrator dispatch (Medium)
- [ ] `develop-story` Step 5 prep dispatches mapper
- [ ] Pass matrix path to `/qa-story` invocation

### Phase 4 — `/qa-story` consumption (Medium)
- [ ] Skip internal mapping when arg present
- [ ] Use matrix in coverage assessment

### Phase 5 — Validation (Low)
- [ ] Run on story with multiple ACs and partial coverage
- [ ] Confirm gate decision unchanged vs baseline

## 9. Success Criteria

**Functional**:
- [ ] Matrix generated by subagent, not main context
- [ ] `/qa-story` consumes matrix when arg present
- [ ] Without arg, behaviour unchanged

**Performance**:
- [ ] Step 5 main reads reduced ≥40%

**Quality**:

**Migration**:
- [ ] None — backwards compatible

## 10. Risk Assessment

**Medium**: matrix misses files (false-clear coverage) → wrong gate. Mitigation: subagent must include "uncertainty" column when grep yields ambiguous matches.

## 11. Rollback Plan

Drop `--traceability-matrix` arg from orchestrator call → `/qa-story` reverts to internal mapping.

# Technical Task: Pipeline docs: QA loop, resume and artifacts

**Status:** Ready for Review
**Review**: ✅ All review recommendations from `task.196.review.1.pipeline-docs-qa-loop-and-artifacts.md` implemented 2026-10-19
**GitHub Issue**: [#599](https://github.com/Gamaroff/agent-skills/issues/599)

## 1. Overview

Bring the develop-pipeline docs in line with how the QA loop routes, how a halted run resumes, and which artifacts a run writes.

**Scope**: 31 confirmed findings (21 medium, 10 low) across 15 docs, from the 2026-10-07 doc-drift audit ([report](../../../.agents/plans/doc-drift-audit-2026-10-07.md)). The plan file lists every finding with its evidence and fix.

**Key deliverables**:

1. Each listed doc says what the current sources do, finding by finding.
2. A re-check of every finding before it is edited, so a finding fixed since the audit is closed rather than re-edited.
3. Link checks green on every changed doc (`doc-links.js` locally; the CI link checker on the PR for `docs/**`).

---

## 2. Motivation

### Current Problems

1. The develop-task and develop-story READMEs, architecture.md, workflows.md, troubleshooting.md and the quickstarts describe the QA loop as routing on the gate token (CONCERNS / FAIL → qa-fix), list five or six artifacts where a run writes nine or more, name review reports by date instead of sequence number, and omit the resume paths shipped since v0.52.0 (QA re-entry after a loop-limit HALT, re-entry after a DoD-gaps fix).
2. The docs predate most of the 401 commits since `v0.52.0`, so a reader following them is misled even where nothing fails outright.
3. Each finding was confirmed by an auditor and a second agent that tried to refute it, against `develop` at `a0e135a6`; none is fixed yet.

### Benefits

1. A reader following these docs gets the behaviour the skills have today.
2. The next release ships docs that match it.
3. Fewer support questions caused by docs describing behaviour that changed.

Every finding's evidence is a `path:line` into these, recorded in the plan and the audit report.

### Target Architecture

Every diagram and table that shows the QA loop routes on the open `top_issues[]` queue (a CONCERNS gate with an empty queue hands to Step 5c), every artifact list matches what a run writes (review.N, pr-review.N, sprint-review-summary.md, per-cycle QA commits), and the resume sections describe the shipped re-entry paths.

### Important Clarifications

- **Findings are from 2026-10-07 at `a0e135a6`.** Phase 0 re-checks each against the tree at the time of work: a finding fixed since then is marked closed, not re-edited, and one whose source moved is re-cited.
- **Edit sources, not copies.** `skills/*/references/` files are generated by `npm run bundle`; no finding points at one.
- **Sibling tasks.** task.197, task.198, task.199 cover the rest of the audit. They touch different findings; where two tasks edit the same file the edits are in different sections (task.197 also edits `docs/standards/task-documents.md`, in its Branch strategy section).
- **Some docs take edits from findings filed under another doc.** RUNBOOKS-13 and RUNBOOKS-15 also edit `docs/runbooks/task-development.md`; SKILL-READMES-STANDARDS-13 and -14 also edit `skills/develop-story/README.md`. The per-doc counts above are findings filed against each doc, not edits it receives.
- **Prettier does not check Markdown here.** `.prettierignore` excludes `*.md`, so `prettier --check` on a changed doc passes without reading it. The format check for this task is `doc-links.js`, not Prettier.
- **The CI link checker does not reach `skills/*/README.md`.** `.github/workflows/docs-link-check.yml` checks changed files under `docs/`, `examples/`, `README.md`, `AGENTS.md` and `CONTRIBUTING.md` only. `doc-links.js` checks relative link targets in any file but not `#anchors`, so an anchor in a changed skill README is checked by hand against the target's headings.

## 11. Rollback Plan

### Immediate Rollback (< 1 hour)

- **Triggers**: a changed doc gives a command that fails, or the link check goes red on `develop`.
- **Steps**: 1) `git revert` the merge commit. 2) Re-run the link check.
- **Validation**: the reverted docs match `develop` before the merge.

### Partial Rollback (1-2 hours)

- **When to use**: one doc's edit is wrong. Revert that file's hunk only.

### Forward Fix (< 4 hours)

- **When to use**: a wording problem with no wrong outcome. Fix forward.

### Rollback Triggers

- **Critical**: a doc that now tells users to run a failing command.
- **Non-critical**: wording.

# Bug Report: Task 217 - Step 5 treats every file as clean when run outside the repository root

**Task**: [Link](./task.217.finding-anchors-advisory-follow-ups.md)
**Bug ID**: TASK-217-BUG-4
**Severity**: MEDIUM
**Priority**: P1
**Status**: Closed
**Found By**: QA Engineer (cycle 2 refute pass, CR-2)
**Date Found**: 2026-10-24

## Description

The Step 5 tree-diff skips call `git diff --quiet -- "$P"` (staged) and
`git diff --quiet HEAD -- "$P"` (range). `P` is root-relative, and git reads a pathspec relative to
the cwd. Run from a subdirectory, the pathspec matches nothing, and `git diff --quiet` exits 0 for a
path that matches nothing. So "unchanged" and "could not look" give the same answer. The block's
comment says the opposite: "when git cannot answer, which skips too". The only thing that asks for
the repository root is the prose sentence above the block.

## Steps to Reproduce

1. Set up as in TASK-217-BUG-3: a staged `a.js` with a further working-tree edit, plus a `sub/`
   directory.
2. Run the committed Step 5 block with `TARGET=staged`, once from the root and once from `sub/`.

## Expected Behavior

Both runs skip CR-1, or the run from `sub/` HALTs.

## Actual Behavior

The run from the root skips. The run from `sub/` prints `apply: CR-1 (a.js)` and exits 0.

## Impact

`--fix` edits a file whose working tree differs from the content that was reviewed. Nothing reports
it.

## Recommendation

At the top of the block, `cd "$(git rev-parse --show-toplevel)"`, and HALT if that fails. Skip a
path that is not in the checked tree rather than trusting the exit code of `git diff --quiet`. Add a
block-test case that runs from a subdirectory.

## Developer Fix Cycle

### Iteration 1

#### Investigation (New → In Progress)

**Date**: 2026-10-24
**Developer**: qa-fix

**Root Cause Analysis**: `git diff --quiet -- "$P"` resolves `P` against the cwd. From a subdirectory the pathspec matched nothing, and `git diff --quiet` exits 0 for a pathspec that matches nothing, so "unchanged" and "could not look" gave the same answer.

**Structural move (qa-fix Step 2.6)**: consolidate. Every MEDIUM on gates 1 and 2 named this one block. The decision now lives in the engine that wrote the record the block reads, and the block only asks for the answer.

#### Fix Implementation (In Progress → Ready for QA)

**Date**: 2026-10-24

**Fix Description**: The comparison no longer runs `git diff`. `--fix-list` reads the checked content (`git cat-file blob :./<path>` or `<sha>:./<path>`, run from the stamp's `root`) and the working-tree file from the same root, then compares the two. A path that cannot be read on either side is skipped with "could not compare", so "could not look" is no longer read as "unchanged". The cwd plays no part.

**Files Modified**:

- `shared/resources/finding-anchors.js`: `--annotate`'s stamp records `tree` (`worktree`, `index`, or `rev` with the SHA) and the absolute `root`. The new `--fix-list` mode reads them and prints the apply list.
- `skills/review-code/SKILL.md`: the Step 5 block calls `finding-anchors.js --fix-list` and binds no target. The prose says the checker decides from its stamp.
- `skills/*/references/finding-anchors.js`: regenerated by `npm run bundle`.
- `shared/resources/tests/finding-anchors.test.mjs`: six `--fix-list` tests (the three trees from the root, a subdirectory and outside the repository; an unreadable side; 13 refusals; the flags it refuses; the JSON shape).
- `skills/review-code/tests/review-code.test.js`: the Step 5 block test annotates with the real checker for each tree and runs the block from the root and from `sub/`.
- `docs/tasks/task.217.finding-anchors-advisory-follow-ups/task.217.qa.2.review-code-step5-cases.json`: 23 probe cases, with the shipped checker in every fixture.

**Testing**: `node --test` on the review-code, review-pr, finding-anchors and checker-blocks suites: 255 pass, 0 fail. Mutation: reading the working tree from the cwd instead of the stamp's root turns the subdirectory test red. The Step 5 probe engages 23/23. Its calibration (a block that ignores the checker's exit) reads `present-but-inert`, 11/23.

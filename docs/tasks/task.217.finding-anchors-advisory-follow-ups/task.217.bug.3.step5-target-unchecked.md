# Bug Report: Task 217 - Step 5 applies every finding when TARGET is not a known target

**Task**: [Link](./task.217.finding-anchors-advisory-follow-ups.md)
**Bug ID**: TASK-217-BUG-3
**Severity**: MEDIUM
**Priority**: P1
**Status**: Closed
**Found By**: QA Engineer (cycle 2 refute pass, CR-1)
**Date Found**: 2026-10-24

## Description

The `/review-code` Step 5 apply-list block (`skills/review-code/SKILL.md`, the block that opens
`# Which findings Step 5 may edit.`) binds `TARGET="{target: worktree | staged | range}"` and never
checks it. Its two tree-diff skips compare `"$TARGET" = staged` and `"$TARGET" = range`. Any other
value turns both skips off, and every finding reads as applicable. That covers the placeholder left
unfilled, `--staged`, `Staged` and `pr`. Step 2b validates the same value with a `*) HALT` case;
Step 5 does not.

## Steps to Reproduce

1. In a temporary repository, commit `a.js`. Stage an edit, then edit the file again on top, so the
   working tree differs from the index.
2. Write a stamped findings file: one finding at `a.js:1` with `anchor_check: "ok"`.
3. Run the committed Step 5 block with `{findings-json}` filled in, and `TARGET` set to `staged`,
   then to `--staged`, then left unfilled.

## Expected Behavior

`TARGET=staged` prints `skipped — working tree differs from the staged content that was reviewed:
CR-1 (a.js)`. An unknown `TARGET` HALTs with nothing applied.

## Actual Behavior

`staged` skips, as expected. `--staged` and the unfilled placeholder both print
`apply: CR-1 (a.js)` and exit 0.

## Impact

`--fix` edits a line the checker never saw. This is the outcome the cycle-1 skips exist to prevent.
The fix cycle chose not to add the check, because the one-slot `fence:` probe leaves `TARGET` at its
literal placeholder, and a HALT would fail every Step 5 probe case.

## Recommendation

HALT on a `TARGET` outside `worktree|staged|range`, as Step 2b does, and add a case to the block
test. Keep the Step 5 probe control reachable some other way, for example a second probe slot or a
case-level fill. Do not drop the check to keep the probe reachable.

## Developer Fix Cycle

### Iteration 1

#### Investigation (New → In Progress)

**Date**: 2026-10-24
**Developer**: qa-fix

**Root Cause Analysis**: The Step 5 block re-bound `TARGET` from a placeholder, separately from Step 2b. Its tree-diff skips compared `TARGET` against two literals, so any other value, the unfilled placeholder included, ran neither skip. The cycle-1 fix chose not to validate `TARGET`, because the one-slot `fence:` probe leaves it at its placeholder.

**Structural move (qa-fix Step 2.6)**: consolidate. Every MEDIUM on gates 1 and 2 named this one block. The decision now lives in the engine that wrote the record the block reads, and the block only asks for the answer.

#### Fix Implementation (In Progress → Ready for QA)

**Date**: 2026-10-24

**Fix Description**: The target is no longer an input to Step 5. Step 2b's checker already knows which tree it read, so `--annotate` now writes it into the stamp, and `finding-anchors.js --fix-list` reads it from there. A value that can be mis-bound no longer exists, so there is nothing to validate. The block keeps one input (`{findings-json}`), so the probe still reaches it. A stamp written by an older checker carries no tree and is refused.

**Files Modified**:

- `shared/resources/finding-anchors.js`: `--annotate`'s stamp records `tree` (`worktree`, `index`, or `rev` with the SHA) and the absolute `root`. The new `--fix-list` mode reads them and prints the apply list.
- `skills/review-code/SKILL.md`: the Step 5 block calls `finding-anchors.js --fix-list` and binds no target. The prose says the checker decides from its stamp.
- `skills/*/references/finding-anchors.js`: regenerated by `npm run bundle`.
- `shared/resources/tests/finding-anchors.test.mjs`: six `--fix-list` tests (the three trees from the root, a subdirectory and outside the repository; an unreadable side; 13 refusals; the flags it refuses; the JSON shape).
- `skills/review-code/tests/review-code.test.js`: the Step 5 block test annotates with the real checker for each tree and runs the block from the root and from `sub/`.
- `docs/tasks/task.217.finding-anchors-advisory-follow-ups/task.217.qa.2.review-code-step5-cases.json`: 23 probe cases, with the shipped checker in every fixture.

**Testing**: `node --test` on the review-code, review-pr, finding-anchors and checker-blocks suites: 255 pass, 0 fail. Mutation: reading every stamp as `worktree` turns 3 engine tests red. The Step 5 probe engages 23/23. Its calibration (a block that ignores the checker's exit) reads `present-but-inert`, 11/23.

**Verification Steps for QA**:

1. Stage `a.js`, then edit it on top. Run Step 2b with `--index`, then Step 5: `skipped — working tree differs from the staged content that was reviewed: CR-1 (a.js)`.
2. There is no `TARGET` in Step 5 to leave unfilled. `grep -n '{target:' skills/review-code/SKILL.md` finds only Step 2b.
3. Strip `tree` from the stamp. Step 5 HALTs with "nothing applied".

## Summary

`security-probe.mjs` now refuses input it cannot score instead of running it and saying nothing: an
unknown `direction` or `sink` in a cases file, and an entry that does not exist. A bundled copy
finds the repository from git, and the run record says why each declined case was declined.

## What Was Delivered

### Success Criteria Met

- [x] A cases file with an unknown `direction` exits 2 `bad-cases` and writes no record
- [x] An unknown `sink` is refused the same way
- [x] A bundled copy defaults its repo root to the git top level
- [x] A missing entry with `--record` exits 2 `entry-not-found` and writes no record (all six entry forms)
- [x] `--json` prints `{reason, …}` for both refusals
- [x] The run record carries `declined_cases` (`{id, reason, detail}`)
- [x] `npm test`, `bundle:check` and `prettier --check .` pass
- [x] CHANGELOG states the refusals and `declined_cases`

### Key Features Implemented

- **`validateCases` / `describeBadCase`**: checks every supplied case's `direction` and `sink` before anything runs; `main` and `runProbeSpec` both call it.
- **`defaultRepoRoot`**: uses `git rev-parse --show-toplevel` from the caller's checkout, falling back to two levels up.
- **Entry-exists check**: `main` refuses a missing entry before `preflightRecord`, so no failed run lands in the record.
- **`declined_cases`**: `toRecordEntry` carries each declined case's id, reason and detail.

### Architecture/Design Decisions

Both refusals return before `preflightRecord`, so a run the engine cannot set up writes nothing.
`runProbeSpec` keeps its `entry-not-probeable` decline for library callers; only the CLI refuses a
missing entry.

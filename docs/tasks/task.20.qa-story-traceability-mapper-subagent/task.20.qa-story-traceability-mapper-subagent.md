# Task 20 — Pre-`/qa-story` traceability mapper subagent

**Status**: Accepted
**Review**: ✅ All review recommendations from `task.20.qa-story-traceability-mapper-subagent.review.2026-05-09.md` implemented 2026-05-09

> Detailed implementation guide: [task.20.plan.qa-story-traceability-mapper-subagent.md](task.20.plan.qa-story-traceability-mapper-subagent.md)

## 1. Overview

`/qa-story` builds an AC → spec-files → src-files traceability matrix internally. Today this happens in main context, requiring multiple greps and reads.

**Scope**: extract this mapping into a read-only Explore subagent dispatched by the orchestrator (or by `/qa-story` itself in lite-mode) before assessment begins. `/qa-story` accepts a caller-supplied matrix and skips internal mapping when provided.

## 2. Motivation

- Mapping greps + file reads bloat main context before assessment work begins.
- Caller-supplied matrix lets `develop-story` orchestrator parallelise mapping with other Step-5 prep.

## 3. Technical Background

**Current**: `skills/qa-story/SKILL.md` performs traceability mapping inline as part of its review.

**Target**: orchestrator dispatches Explore: "Read story <path>, extract ACs, grep for related spec files (`*.spec.*`, `*.test.*`) and src files, return matrix as markdown table." Result written to a path under `<story-dir>/.summaries/`. `/qa-story` is invoked via the Skill tool with `args="traceability_matrix=<path>"`; absent arg → existing internal mapping behaviour.

## 4. Scope

**In**: traceability mapping handoff.
**Out**: `/qa-story` assessment logic; gate file generation.

## 5. Breaking Changes

None — additive contract; absent matrix arg → existing behaviour.

## 6. Implementation Plan

### Phase 1 — Define matrix schema (Low)
- [x] Markdown table: AC | Spec files | Src files | Coverage notes
- [x] Document Skill arg form: `args="traceability_matrix=<path>"` (path under `<story-dir>/.summaries/`)

### Phase 2 — Author Explore prompt (Low)
- [x] Strict matrix output; ≤30 rows
- [ ] Patterns to grep configurable per project _(future work — current implementation hardcodes `*.spec.ts`, `*.test.ts`, etc. A `skills-config.yaml` hook for `qa.specPatterns`/`qa.srcPatterns` is needed for multi-language projects)_

### Phase 3 — Wire orchestrator dispatch (Medium)
- [x] `develop-story` Step 5 prep dispatches mapper (edit `shared/resources/develop-pipeline-step-5-6-qa-loop.md`)
- [x] Pass matrix path via Skill `args="traceability_matrix=<path>"` on `/qa-story` invocation

### Phase 4 — `/qa-story` consumption (Medium)
- [x] Parse `traceability_matrix=<path>` from Skill `args`
- [x] Skip internal mapping when arg present; use matrix in coverage assessment

### Phase 5 — Validation (Low)
- [ ] Run on story with multiple ACs and partial coverage
- [ ] Confirm gate decision unchanged vs baseline

- [x] Matrix generated by subagent, not main context
- [x] `/qa-story` consumes matrix when arg present
- [x] Without arg, behaviour unchanged

**Performance**:
- [x] Mapping no longer occurs in main context (reads offloaded to Explore subagent)

**Quality**:
- [ ] Gate decisions stable on golden cases (validated in QA)

**Migration**:
- [x] None — backwards compatible

## 10. Risk Assessment

**Medium**: matrix misses files (false-clear coverage) → wrong gate. Mitigation: subagent must include "uncertainty" column when grep yields ambiguous matches.

## 11. Rollback Plan

Drop `--traceability-matrix` arg from orchestrator call → `/qa-story` reverts to internal mapping.

# Technical Task: A git-name sink for classifiers of repository names

**GitHub Issue**: [#955](https://github.com/Gamaroff/agent-skills/issues/955)

**Status:** Ready for Review
**Review**: ✅ All review recommendations from `task.329.review.1.git-name-probe-sink.md` implemented 2026-11-26

---

## 1. Overview

The security probe sends a boundary the hostile inputs of one corpus sink. `isDocsPath` decides whether a
name that `git diff --name-only` printed is documentation. There is no sink for that, so the security
agents use `path`. Two `path` cases assume a filesystem: one decodes `%2f`, one follows a symlink.
`isDocsPath` does neither, and neither is wrong for a git name. So both cases "reproduce", and task 325's
finalise run stopped on them (`task.325.dod.1`).

**Scope**: a new `git-name` sink in the corpus, the prompts that choose a sink, and a test that proves the
cases bite.

**Key deliverables:**

- `git-name` in `SINKS`, with hostile and legitimate cases and its `.md` section;
- the two security prompts and `probe-boundary-rule.md` route a name classifier to it;
- a test that runs `isDocsPath` through the sink at HEAD, where every case holds, and through broken
  copies, where each hostile case reproduces.

**Expected outcome**: a probe of `isDocsPath` tests what the function promises. Task 325's finalise
re-run plans `--sink git-name` and has no false reproductions.

---

## 2. Motivation

### Current Problems

1. **A false failure blocks acceptance.** `path.encoded-traversal` (`..%2f..%2fetc%2fpasswd`) and
   `path.symlink-escape` (`uploads/link-to-etc/passwd`) both reproduced on `isDocsPath` in
   `task.325.dod.1`. Neither is a defect: git prints `%2f` as three literal characters, and a name is not
   opened. Fix-and-recheck refused, since there is no code fix.
2. **The nearest sink is the wrong one.** `security-review-prompt.md:87` sends "what filesystem location
   is read or written" to `path`. Nothing routes "which class a name belongs to", so agents choose `path`.
   The prompt itself says not to force a control into the nearest sink.
3. **The real hostile names go untested.** `.git/config`, `docs/.GIT/x.md`, `docs//a.md` and the
   pipeline's own config file are what a docs classifier must refuse. `path` holds none of them.

### Benefits of Solution

1. Task 325, and any later work on `isDocsPath`, is probed with cases that can fail for a real reason.
2. Each of the classifier's refusals is held by a corpus case that a broken copy turns red.
3. The routing rule says which sink fits a name classifier, so a later agent does not have to guess.

## 3. Technical Background

Every result below was run on 2026-11-26 at `684b2db38` (`develop`).

### Current Architecture

- **Sinks.** `shared/resources/security-input-corpus.mjs:29` *(`export const SINKS`)* lists seven sinks.
  `CORPUS` (`:1081`) maps each to its cases, `SINK_BLURB` (`:1174`) gives each its heading prose, and
  `MATERIALISED_SINKS` (`:98`) holds only `filename`. The `.md` peer's `## The cases` (`:86`) is
  generated by `renderCorpusTables()`, and a parity test holds the two equal. The `.md` peer's
  `:387` *(`The six sinks are a judgement`)* is already one behind.
- **The `path` cases.** `security-input-corpus.mjs:576` *(`const PATH = sinkCases("path"`)*. They model
  a filesystem API, which is right for code that opens a file. This task does not change them.
- **The classifier.** `shared/resources/ci-tree-equivalence.js:167` *(`function isDocsPath`)* refuses
  an empty name, control characters, an empty, `.` or `..` segment, a gitlink, a `.git` segment in any
  case, the config basename and a name `normalisePath` would change. Then it matches the globs. It never
  decodes and never touches the disk.
- **How the probe scores a function.** `shared/resources/security-probe.mjs:484`
  *(`returned === false`)*: `false`, `null`, `undefined`, `{ ok: false }` or a throw is `rejected`.
  Anything else is `accepted`. So `isDocsPath` returning `false` is a refusal.
- **The sink choice.** Three documents say how to pick a sink:
  `shared/resources/finalise-dod-security-prompt.md:159` *(`Sinks: \`url-authority\``)*,
  `shared/resources/security-review-prompt.md:79`, with its table at `:83`–`:90`, and
  `shared/resources/probe-boundary-rule.md` § `boundary: internal` (`:186`). The test
  `shared/resources/tests/security-input-corpus.test.mjs:580` *(`const ENUMERATIONS`)* fails when either
  prompt's list misses a sink, and is derived from `SINKS`. So adding a sink turns it red until both
  prompts name it.
- **Counts.** `security-input-corpus.test.mjs:56` *(`const FLOORS`)* sets each sink's minimum hostile
  and legitimate count. Growing is allowed and shrinking fails. A sink with no entry there is the
  defect this task must not ship.
- **The two extra hostile names.** `docs/a\tb.md` (tab) and `.git` are both refused at HEAD. With the
  control-character line removed, the tab name reproduces. With the `.git` line removed, `.git`
  reproduces. Both were measured the same way as the table below.

### Measured: `isDocsPath(name, ["**"])` at `684b2db38`

| Name | Result | Direction in the new sink |
| :-- | :-- | :-- |
| `.git/config`, `docs/.git/x.md`, `docs/.GIT/x.md` | false | hostile |
| `docs/../x.md`, `/docs/a.md`, `./docs/a.md`, `docs//a.md`, `docs/` | false | hostile |
| `docs/a␁.md` (U+0001), `docs/a␀.md` (NUL) | false | hostile |
| `skills-config.yaml`, `docs/skills-config.yaml` | false | hostile |
| `docs/a%2fb.md`, `..%2f..%2fetc%2fpasswd` | true | legitimate |
| `uploads/link-to-etc/passwd` | true | legitimate |
| `docs/notes (draft).md`, `docs/c++.md`, `docs/café.md` | true | legitimate |
| `docs/.gitkeep`, `docs/archive..2026.md` | true | legitimate |

### Measured: which broken copy each hostile case catches

Each refusal line removed from a scratch copy of `ci-tree-equivalence.js`, with `["**"]`:

| Line removed | Hostile cases that then reproduce |
| :-- | :-- |
| control characters | `docs/a␁.md`, `docs/a␀.md` |
| empty/`.`/`..` segment | `docs/../x.md`, `docs//a.md`, `docs/` (the corpus uses `docs/guides/`, which reproduces the same way: `docs/` is restated in the DoD prompt, which the prompt-contract test refuses) |
| `.git` segment | `.git/config`, `docs/.git/x.md`, `docs/.GIT/x.md` |
| config basename | `skills-config.yaml`, `docs/skills-config.yaml` |
| segment **and** `normalisePath` | adds `/docs/a.md`, `./docs/a.md` |

`/docs/a.md` and `./docs/a.md` are each refused by two checks, so only the paired mutation reaches them.
The empty name `""` never reproduces, even with the empty, segment and normalise checks all removed,
because `matchesAnyGlob("", ["**"])` is false. Git never prints an empty name, so it is **not** a case
here. `path.empty` already covers it for a filesystem API.

### Target Architecture

- A sink `git-name`: "a classifier deciding **which class a repository-relative name belongs to**, as
  git prints it, without opening it". It is not materialised: the input is passed as the name.
  - **Hostile**: names no classifier may put in a permissive class, whatever its patterns. These are
    repository internals, names not in git's canonical form, control characters, and the pipeline's own
    config file.
  - **Legitimate**: real names with characters a filesystem-minded check refuses. A legitimate case
    must be accepted under `["**"]`.
- The prompts' sink lists and the review prompt's table gain the sink, with the rule: a name only
  compared against patterns is `git-name`, and a name passed to a filesystem call is `path`.
- `ci-tree-equivalence.js#isDocsPath` joins the finalise prompt's *Entries disqualified from
  `internal`* table against `git-name`. This is a routing record, not a new disqualification: its input
  is git output, not a pipeline artefact, so it was never eligible for `internal`.

### Important Clarifications

- **`path` is not narrowed.** Code that opens a file keeps the decoding and symlink cases.
- **The sink is general, and one case is this repository's own.** `skills-config.yaml` is the
  pipeline's config, and its `why` says so.

## 8. Testing Strategy

### Unit Tests

| Case | Expected |
| :-- | :-- |
| `corpusFor("git-name")` | `FLOORS` holds `git-name: { hostile: 14, legitimate: 8 }`; ids prefixed `git-name.` |
| the parity test of the `.md` tables | passes after regeneration |
| the enumeration test (`:580`) | names `git-name` in both prompts |
| `isDocsPath` through `--sink git-name` with `[["**"]]` at HEAD | every hostile rejected, every legitimate accepted |
| the same, with each line of § 3 removed in a temp copy | exactly the cases § 3 lists reproduce |

The cases are the measured ones. Hostile: the 12 names in § 3's table, plus `docs/a\tb.md` (tab) and
`.git`, for 14. Legitimate: the 8 in § 3's table.

The temp copy lives in a `mkdtemp` directory removed in a `finally`.

**Tests that enumerate `SINKS` and react to the new member** (`git grep -n "SINKS" -- '*.test.*'`):
`security-input-corpus.test.mjs` (the `FLOORS` table, the both-directions check, the prompt enumeration
check at `:580`, and the `.md` parity check), and `security-probe.test.mjs:7289`
*(`every case of every sink's corpus passes`)*, which runs `validateCases` over every sink's cases.
`skills/review-security/tests/review-security.test.js:117` only checks that a fixture's sink is in
`SINKS`, and needs nothing.

**Command**: `command node --test shared/resources/tests/security-input-corpus.test.mjs shared/resources/tests/security-probe.test.mjs`

### Mutation Tests

Each alone turns a named test red:
- `git-name` dropped from `SINKS`;
- one hostile case flipped to legitimate;
- `git-name` dropped from either prompt's list;
- the paired segment and normalise mutation applied without the test expecting `/docs/a.md`.

### Control Case

`path.encoded-traversal`'s input appears in `git-name` as **legitimate**. A test that read `path`'s
direction would fail on it.

### Consumer Tests

`npm run test:remote` runs the whole suite.

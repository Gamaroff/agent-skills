# Technical Task: The skill-resolution rule covers a Skill result with no Base directory line

**Status:** Ready for Review

---

## 1. Overview

Task 311 added `skill-resolution.md`, the rule the develop pipelines follow after every sub-skill load. Its table covers four outcomes. It does not cover a Skill result that has no `Base directory for this skill:` line, so the orchestrator has no instruction for it. This task adds that case to the rule and re-bundles the copies.

**Scope**: one rule document (`shared/resources/skill-resolution.md`), its three bundled copies, one CHANGELOG line. No engine change.

Source: advisory CR-1 in the task 311 QA report (`task.311.qa.1.*`, `recommendations.future` in the gate).

---

## 2. Motivation

### Current Problems

1. **An uncovered case**: with no `Base directory` line, the orchestrator has nothing to pass as `--base-dir`. The empty value returns `usage` (exit 2), and the table reads `usage` as "the call is wrong, fix the call". Fixing the call is impossible when the input does not exist.
2. **Two readings, no rule**: one run may stop and another may carry on. Both are guesses, and a pipeline that is meant to run hands-free should not guess.

### Benefits of the fix

1. **One stated behaviour** for an absent line, in the same table as the other four outcomes.
2. **No engine or test churn**: the engine already refuses an empty `--base-dir` with `usage`.
3. **Consistency**: the answer matches the one the rule gives for `unreadable`, which is the other case where identity is unknown.

---

## 3. Technical Background

### Current Architecture

- The rule document's table lists `repo`, `shadowed`, `unreadable`, `usage` (`shared/resources/skill-resolution.md`, table under "After every load").
- The engine refuses an empty base directory: `skill-resolution.js:66` returns `{ reason: "usage", message: "--base-dir is required" }` (grep: `git grep -n 'base-dir is required' -- shared/resources/skill-resolution.js`).
- The rule's `unreadable` row already says to log a warning and proceed with the loaded copy, because identity is unknown.
- Three bundled copies exist: `skills/develop-{bug,story,task}/references/skill-resolution.md` (grep: `ls skills/*/references/skill-resolution.md`).

### Target Architecture

The rule gains a short paragraph, placed directly under the table:

> **No `Base directory` line.** If the Skill result carries no `Base directory for this skill:` line, there is no identity to check, and the empty `--base-dir` would only return `usage`. Do not run the check. Treat it as `unreadable`: log "skill `{skill-name}` loaded with no Base directory line — identity unchecked" in the Issues Log and proceed with the loaded copy.

The engine is unchanged. The choice (proceed, as for `unreadable`, and not read the repository copy) is the one this task's author recommends. It keeps the hands-free run moving, and it is the same stance the rule already takes when identity is unknown.

### Important Clarifications

- This is a documentation change. There is no behaviour to mutation-prove: the success criteria rely on the bundle, link and fast-gate checks, and on a read-through of the new paragraph.

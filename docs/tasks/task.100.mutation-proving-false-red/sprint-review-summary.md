## Summary

`shared/resources/mutation-proving.md` — the reference that tells every skill in this library how to establish a test would actually fail — handled only half its subject. It covered the **false GREEN**: a mutant that survives when it should have died, with a `diff` check to prove the mutation applied. It said nothing about the mirror.

That asymmetry matters more than it sounds. A green run that should have been red *announces itself*: you predicted red, you got green, so you investigate. A red run that should have been green announces nothing — red was the prediction, red is what arrived, and the reading goes into the matrix as a kill.

This task adds the missing half.

## What shipped

A new section, `## When the proof goes red for the WRONG reason`, placed directly after the section it mirrors so a reader asking *"why did my mutant survive?"* meets *"and why did it die?"* in the same breath.

- **The asymmetry, stated.** A false GREEN leaves a survivor, and a survivor is a finding. A false RED writes `dead` into a row nothing ever executed — certifying coverage that was never exercised, while looking exactly like diligence.
- **A four-row table**, mirroring the existing three-row one: *a real kill*, *environmental refusal*, *invocation error*, *wrong thing mutated*.
- **Three mechanical checks plus one judgement.** The three — baseline GREEN with the *exact* command, one known-bad mutation red and killed by its **named** case, and the applied-check `diff` — are cheap and stated as such. The fourth, that the mutation must change the *value* under test rather than merely produce a diff, carries no command and no time claim, because nothing external can perform it.

## Evidence base

Five invalid probe readings from **two independent runs in two repositories** (tinker-city task.103, agent-skills task.95). Three were false REDs. Two of them would have recorded a mutation matrix as complete having executed **zero** tests — and in one, the reading was convincing precisely because the repository's own node-major guard was working exactly as designed and refusing to run.

## The QA loop is worth reading

| 2 | CONCERNS 85 | **The fix for cycle 1 was itself wrong.** It replaced the constant with `2/N`, but the procedure runs the suite *twice* per invariant, so the matrix pays ~2N and every percentage was 2× too high. All three of cycle 2's findings were in text cycle 1 had introduced. |

Cycle 2 is a mandatory **full refute pass** over the whole diff rather than a narrowed re-read of the fix. A narrowed cycle 2 would have seen the constant correctly removed and passed — shipping a wrong number in the document that exists to stop wrong numbers.

## Known limitations

- The fourth check is a judgement. Nothing external can verify that a mutation expresses the behaviour the author meant to break, and the document says so rather than dressing it as a command.
- The rule models the failure shapes that have been *observed*. As shape 5 of the six shapes already warns about itself: counting the spellings you have closed tells you nothing about the ones you have not.

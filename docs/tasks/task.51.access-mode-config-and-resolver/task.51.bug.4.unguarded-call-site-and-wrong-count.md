# Bug Report: Task 51 - An unguarded call site remains; the "16 call sites" count is wrong

**Task**: [Link](./task.51.access-mode-config-and-resolver.md)
**Bug ID**: TASK-51-BUG-4
**Severity**: HIGH
**Priority**: P0
**Status**: Ready for QA
**Found By**: QA Engineer
**Date Found**: 2026-08-17

## Description

The task asserts "all 16 call sites" across 15 skills are guarded. An independent sweep finds
**19 source/dot-source sites across 16 skills**, of which **18 are guarded and one is not**:

`skills/review-code/SKILL.md:96`

```bash
. "$(dirname "$0")/references/resolve-platform.sh"   # adjust to the bundled path in this install
```

`review-code` was never in the task's site list, yet it bundles `references/resolve-platform.sh`
(regenerated by this very branch). The undercount arises because `qa-task` and `qa-story` each hold
**two** sites and were counted once apiece, and because a `.`-style dot-source does not match a grep
for `source `.

## Steps to Reproduce

```bash
cd skills/review-code
AGENT_SKILLS_ACCESS_TRACKER=bogus bash -c '. "references/resolve-platform.sh"; echo "REACHED BODY AT=[$ACCESS_TRACKER]"'
```

## Expected Behavior

The body does not run; the caller exits non-zero.

## Actual Behavior

```
❌ … "bogus" is not a recognised value.
REACHED BODY AT=[]
```

The run continues past a rejected access value — and `ACCESS_TRACKER` is left **empty**, which is
worse than the permissive `full` default the task set out to prevent, because downstream `[ "$ACCESS_TRACKER" = full ]`
tests and `[ -z ... ]` tests both behave unexpectedly.

## Impact

This is precisely the failure the task exists to close — *"a validator that writes to stderr and
returns non-zero halts nothing unless a caller checks"* — still live in the repo after the task
claimed to have closed it. Falsifies Success Criterion 5.

The wrong count is replicated into `CHANGELOG.md`, `shared/resources/platform-detection.md`
("All sixteen use the guarded form"), `shared/resources/README.md`, the task's Change Log row, and
all 28 bundled `platform-detection.md` copies.

## Related

`skills/jira-sprint-retrospective/SKILL.md:144` **executes** the resolver
(`bash ./references/resolve-platform.sh`) rather than sourcing it. `VCS` never reaches the caller,
and on a rejection it prints `return: can only 'return' from a function or sourced script` and
**exits 0** — fail-open. Not a `source` site, but the same class of hole.

## Recommendation

1. Guard `skills/review-code/SKILL.md:96`.
2. Fix `jira-sprint-retrospective:144` to source rather than execute (or make the script safe to
   execute).
3. Correct the count to 19 sites / 16 skills everywhere it appears, then re-bundle.
4. **Add the grep assertion the Risk Assessment already claims exists** (see TASK-51-BUG-5) — it is
   the only thing that would have caught this.

## Developer Fix Cycle

### Iteration 1

#### Investigation (New → In Progress) — 2026-08-17

Two independent causes. The site was missed because the sweep grepped for `source ` and
`review-code:96` uses a `.` dot-source. The count was wrong because `qa-task` and `qa-story` each
hold two sites and were counted once apiece.

Neither would have mattered if the claimed grep assertion had existed — it did not (see BUG-5).

#### Fix Implementation (In Progress → Ready for QA) — 2026-08-17

- Guarded `skills/review-code/SKILL.md:96`.
- `skills/jira-sprint-retrospective/SKILL.md:144` changed from `bash ./references/resolve-platform.sh`
  (executed — variables never reach the caller, and a rejection exits 0) to
  `source … || exit 1`, with a sentence saying why it must be sourced.
- Corrected the count everywhere it appears: **18 sourcing forms across 16 skills**, all guarded.
  Re-derived mechanically rather than by hand — `platform-detection.md`, `shared/resources/README.md`,
  the task document, the Change Log row and the CHANGELOG.

**Files**: `skills/review-code/SKILL.md`, `skills/jira-sprint-retrospective/SKILL.md`,
`shared/resources/platform-detection.md`, `shared/resources/README.md`, `CHANGELOG.md`,
the task document, plus regenerated bundled copies.

**Testing**: §11 now greps the repo and fails on any unguarded site, and a second assertion fails if
any skill executes the resolver instead of sourcing it.

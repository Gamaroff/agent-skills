## Summary

Wireframe-to-component mapping (task 243) was opt-in, and a project only found it by reading the configuration reference. Now, when `create-story` or `create-task` adds a wireframe and no `ui:` block exists, they detect the project's components and offer to set mapping up. A "never" is recorded as a decline that every skill respects. On the first run, `resolve` offers catalogue-derived candidates even when the map is empty.

### Key Features Implemented

- **Recorded decline:** "Never" writes `wireframeMap: false`, and no skill offers again

- **Hand-written rows guide:** the mapping procedure documents how to write map rows by hand, including the sibling-context and icon-glyph limits a consumer found

- 16 bundled `references/` copies, regenerated by `npm run bundle`

### Architecture/Design Decisions

- `detect` is read-only and bounded: a fixed barrel list, one level of `packages/*` and `libs/*`, and `docs/` to depth 4. The authoring skills can call it without risk.
- `configure` edits `skills-config.yaml` line by line instead of re-serialising it, so comments, ordering and unrelated keys survive. It fills blank keys before inserting missing ones.
- The offer belongs to the authoring skills only. A test enforces that no develop pipeline step calls `detect` or `configure`.

### Dependencies

- **New Dependencies Added:** None
- **Breaking Changes:** None. `false`/`off` used to be read as a path; it now means a decline, as the CHANGELOG notes.

## Demo Notes

### How to Verify

1. In a repository with `src/components/index.ts` and no `ui:` block, run `command node shared/resources/wireframe-map.js detect --json`. It reports `unset` with a barrel proposal.
2. Run `configure --map docs/wireframe-map.md --barrel src/components/index.ts --json`. Then `detect` reports `configured`.
3. In a fresh copy, run `configure --decline --json`. `detect` then reports `declined`, and `ensure` writes nothing.

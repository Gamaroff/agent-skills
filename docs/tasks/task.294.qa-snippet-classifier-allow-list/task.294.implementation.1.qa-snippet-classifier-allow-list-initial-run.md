- **Design changed during implementation (decision for you):** the plan's first design refused every stored command substitution (`x=$(…)`) and every non-digit operand of an arithmetic test. That broke real shipped blocks pinned by task 191 (`REVIEW_N=$(next_numbered …)`) and task 77's predicate. I measured `[`, `test` and `[[` under real bash and zsh: `[` and `test` evaluate no operand, only bash `[[` does. The final rule admits stored values and `[`/`test` operands, and refuses non-digit text only where bash evaluates it. Docs-scan cost fell from 21 blocks to 5 of 256.
- Existing tests changed, with reason: 5 controls that pinned a bare name inside arithmetic, `${a[0]}`/`${@:$1}`-style operators or a subscripted array element as `runnable` now assert both verdicts (earlier layers admit, allow-list refuses) through a `beforeAllowList` helper. The task.293 control list became a table with both verdicts per row.
- Quadratic first draft: re-marking each nested interior made a 20000-deep nest take 59 s. Replaced by one linear sweep with a stack of enclosing tokens (155 ms).
- Mutation proofs (each reverted, 0 markers left): allow-list call removed → 3 tests red; `$((` name check removed → 4 red; `[[` arithmetic check removed → 2 red; `=` command-word check removed → 3 red; helper-rule order swapped → the Phase 5 test red; `mapfile` added to the table → the six-word test red.
- Differential calibration: the mixed `indirect` set formed none of the residuals in 40000 blocks on the OLD engine (instrument blind). Added a `residual` atom set: old engine 10 writes in 5000, new engine 0.

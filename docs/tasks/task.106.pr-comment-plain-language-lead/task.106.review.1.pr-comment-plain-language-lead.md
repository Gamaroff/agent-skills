## 3. Implementation Plan Completeness

**Status:** GAPS FOUND (now closed)

Five phases, each with a risk level, an explicit file list, and checkbox-level changes. Dependencies
between phases are stated. `estimated_effort_hours: 8` is present and plausible against 5 phases and

### Issues

#### Important — the one that mattered

- **[FIXED] Phase 1 cannot land as written: the lead catalogue and `COMMENT_STAGES` are one namespace.**

  `shared/resources/tests/stakeholder-summary.test.mjs:173` asserts *"every catalogue key is a stage
  the engine knows"* — every key of `LEAD_TEMPLATES` must appear in `tracker-comment.js`'s frozen
  `COMMENT_STAGES` list. Task 106 Phase 1 adds `pr-summary`, `board-warning` and `dod-gaps` to
  `LEAD_TEMPLATES`. These are pull-request moments and are never legal `--stage` values for
  `tracker-comment.js`.

  **Verified by mutation, not by reading.** Baseline: 43/43 pass. Adding `pr-summary` to
  `LEAD_TEMPLATES` alone: **42 pass / 1 fail**, with
  `AssertionError: catalogue has "pr-summary", which is not in COMMENT_STAGES`. The mutation was
  reverted immediately (`git checkout --`, tree confirmed clean).

  Neither `stakeholder-summary.test.mjs` nor any resolution appeared in §7 Files Summary or §8
  Testing Strategy — the file guaranteed to go red was not named anywhere in the task.

  **And the obvious fix is the wrong one.** `COMMENT_STAGES` is the validated argument set for
  `tracker-comment.js --stage` (engine L554–566, which exits 2 on an unknown stage). Widening it to
  admit the three would make `tracker-comment.js --stage pr-summary` a legal **tracker-issue**
  comment — letting a pull-request-shaped lead post onto a board card, which is precisely the
  separation this task exists to maintain.

  **Fix applied**: new §5.4 documents the collision, the mutation evidence, and the required shape —
  a second frozen enumeration for the pull-request namespace with the catalogue assertion checking
  membership in the **union**, and `--stage` validation left reading `COMMENT_STAGES` only. Phase 1
  raised from Low to **Medium** risk and given a checkbox for it. A mutation proof was added to §8
  (adding a PR stage to `COMMENT_STAGES` must be rejected by a test), and a success criterion added to
  §9 so the separation is verified rather than assumed.

  Two enumerations here is the correct shape, **not** the enumeration anti-pattern
  ([`docs/reference/anti-patterns.md`](../../reference/anti-patterns.md)): they name two genuinely
  different namespaces, and the union assertion is the single check that keeps them jointly
  exhaustive.

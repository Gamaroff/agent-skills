# agent-skills architecture

> Architecture documentation for the agent-skills repository itself. The repo dogfoods its own pipeline, so it needs the same `docs/architecture/` shards a consumer project would have.
>
> Layout spec: [`docs/standards/architecture-docs.md`](../standards/architecture-docs.md).
> Schema for `skills-config.yaml`: [`docs/reference/configuration.md`](../reference/configuration.md).

## Document scope

This repository is unusual: it is not an application — it is a **library of skills** consumed by other projects. The "architecture" docs here describe how the skill library itself is structured, tested, and shipped, so that pipeline skills (`/develop-story`, `/develop-task`, `/review-*`, `/qa-*`) can ground their work in real conventions when they run **on this repo**.

## Required shards (always loaded)

These three files are loaded into every pipeline run via `devLoadAlwaysFiles`:

- [Coding standards](./concepts/coding-standards.md) — conventions for SKILL.md authoring, script style, frontmatter, naming
- [Tech stack](./concepts/tech-stack.md) — Node 20+, Python 3 scripts, packaging tooling, eval harness
- [Source tree](./concepts/source-tree.md) — where skills, shared resources, docs, evals, and tests live

## Optional shards

None yet. Add new level-2 shards under `docs/architecture/` and link them here as the repo grows (for example, a future `eval-harness.md` or `packaging-pipeline.md` if those areas need deeper treatment).

## Reality check

- This is a **brownfield** document — generated by `/document-existing-project` against an already-established repo. Captures what exists today, not aspiration.
- Skill content (`skills/*/SKILL.md`) is the authoritative source of truth for behaviour. These shards describe **the meta-structure** the skills inhabit, not what each skill does.
- The full skill catalog is generated at [`docs/reference/skill-catalog.md`](../reference/skill-catalog.md) — do not duplicate that information here.
